# 无摩擦模式

模式编号 **12**（`SMART_KNOB_MODE_FRICTIONLESS`），OLED 菜单显示 **FR-LESS**，仪表盘显示 **FR-L**。在本地菜单选择该模式并 SAVE，或者在 Dial 模式下通过现有 CAN function write 写入 `0x8001 = 12`。

原有 0–11 模式的编号、默认参数和控制方式保持兼容。升级会保留已保存的模式选择；原来的 `FREE` 仍是模式 1。

## 控制方式

- 没有弹簧、刻度、端点或恒定转速目标。沿实际转动方向补偿平均运行摩擦与黏性损耗，再叠加按轴角度变化的实测扰动补偿，并可增加虚拟惯量，保留手动加速、减速和换向的能力。用于测量损耗的速度 PI 只存在于诊断测试阶段，不参与正式无摩擦控制。
- 使用完整编码器计数和 8 ms 速度滤波，避免原有 2 Hz 速度估计在停手后继续产生助力。
- 上电时等待 256 个独立、实际更新过的 ADC DMA 样本，再计算电流零点；不再反复读取同一份 DMA 缓冲充当多次采样。零点均值保留为 float32，相电流减去零点后也不取整，避免分数 ADC 计数被丢弃后经 Clarke/Park 变换产生随电角度变化的电流偏差。
- 正常 FR-L 控制在所有速度下都通过 `MotorDriverSetTorqueCurrent` 跟踪 Iq 目标，包含极低速和静止时的零 Iq 闭环。目标为零时也不再切换到原有零电压 PWM，避免绕组短接造成拖动制动；故障、输出关闭和无效采样仍走退出路径。
- 静止附近（速度不超过 0.2 rad/s）目标电流严格为 0，继续使用零 Iq 跟踪。开始助力需速度达到 0.6 rad/s 且连续确认运动 5 ms；停止或换向后有 40 ms 的重新使能等待。低速补偿在 0.2～0.6 rad/s 之间平滑过渡，**0.6 rad/s 即达到完整补偿**，避免慢转时仍因助力衰减而停在齿槽处。
- 平均损耗模型在低速额外加入 `0.30 × Fc × exp(-v² / 9)`，v 的单位为 rad/s。该平滑修正与用户设置的运行摩擦 Fc 成比例，在很低的转速附近最多增加约 30% Fc，随速度上升迅速消退，以覆盖低速测得的额外损耗。它仍受运动确认、低速平滑系数与电流限幅约束，不是静止启动电流。
- 本模式没有按转速衰减或切断助力的限制：取消原有 20～45 rad/s 衰减和 60 rad/s 高速锁定。编码器检查改为校验位置增量与快速度估计是否一致，正常连续转动不再受原有 80 rad/s 采样门槛影响。其他模式保留原有速度逻辑。
- 平均损耗补偿电流的变化速度限制为 1 A/s。角度补偿在启动助力时使用 50 ms 包络渐入，周期分量随后直接跟随角度，避免经过同一电流斜坡后产生随速度增大的相位延迟。平均项限幅时，角度项也按平均项实际输出比例缩放，保留标定相对幅度。平均、角度和惯性电流合成后受独立的 800 mA 硬上限、模式电流上限和安全比例限制。编码器异常跳变、过压、故障、过期控制步骤和输出关闭仍会停止助力。

当前角度前馈由 [`frictionless_calibration.h`](../MyFile/inc/frictionless_calibration.h) 给出，使用实测的每圈 **7、12、14 次**正余弦谐波之和：`I_angle = Σ [S_k × sin(kθ) + C_k × cos(kθ)]`，其中 θ 为机械角度（rad）。相同轴角度下该项在正反方向采用相同符号；它补偿空间周期扰动，不能再乘转动方向的符号。补偿倍率、低速平滑系数和 50 ms 包络也作用于此项。系数来自本模块测量，转子或编码器机械零位改变后应重新识别。

虚拟惯量复用本模式原先闲置的 P/D：P 是额外转子惯量倍数，范围 0～8，0 为关闭；D 是速度记忆滤波时间，单位秒，范围 0.005～0.2，D=0 使用默认 0.020 s。先对速度变化低通，再按 `I_inertia = -0.135 × P × acceleration_filtered` mA 施加惯性反作用，0.135 的单位为 mA/(rad/s²)，表示每倍的估计转子惯量折算电流，不能直接视为 kg·m²。惯性电流独立限制为 ±40 mA，随后参与总电流 800 mA 限幅。它没有保存恒速目标，匀速时逐渐归零；较高惯量可减少速度波动，也会使加速和刹停更重。停止、换向和关闭此功能会清除速度记忆。

这是损耗补偿实现的无摩擦模拟。电机仍存在齿槽力、参数随温度变化和传感器噪声；特别在极低速区，不能严格实现数学上的完全无摩擦或无限时间匀速。它不会用速度锁定来掩盖这些误差。

完整补偿区的平均损耗目标为 `倍率 × [Fc × (1 + 0.30 × exp(-v² / 9)) + B × |v|]`，其中 v 为 rad/s，再叠加上述角度和惯性电流；不能把这个平均项公式当作全部输出。当前倍率下的平均线性项等效为 21.714 mA 与 300.048 µA/(rad/s)，低速另有上述修正。**默认额外 8 倍惯量、10 ms 平滑时间会让加速和刹停明显更重**，需要轻手感时可降低额外惯量。OLED 的 FORCE 是编译默认倍率的百分比，100% 对应当前编译默认倍率；STEP 只调整位置计数宽度。本模式的 P/D 用于虚拟惯量，click 力仍忽略。供电电压、反电动势和电流环能力仍决定实际可达到的速度。

上位机的运行摩擦和电流上限都可调至 800 mA；本模式的 OLED LIMIT 支持 100～800 mA，其他模式仍为 100～450 mA。旧的已保存配置继续保留原值。最终参数可通过上述 CAN 功能写入，或用下述 `--save-mode 12` 命令保存当前编译默认值；临时诊断参数不会自动进入已保存配置。

`0x8108` 是新增的微安单位参数，不使用其他浮点 tuning 的 ×1000 缩放。它参与原有主机控制权和保存事务。Flash 扩展格式升级为 v2、592 字节；v1 的 512 字节配置自动在 RAM 中迁移，保留原有 tuning、Custom 配置、CAN ID 和编码器 offset。

## 可复现的 ST-Link 测试

正式固件默认 **不编译**测试入口。诊断构建显式启用：

```powershell
cmake -S . -B build/frictionless-diag -G Ninja '-DCMAKE_TOOLCHAIN_FILE=cmake/gcc-arm-none-eabi.cmake' '-DCMAKE_BUILD_TYPE=Release' '-DROLLERCAN_MOTOR_DIAGNOSTICS=ON'
cmake --build build/frictionless-diag
openocd -f interface/stlink.cfg -c 'adapter serial 01290141524300143638414B' -c 'transport select swd' -f target/stm32g4x.cfg -c 'adapter speed 1800' -c 'program build/frictionless-diag/ROLLERCAN_standalone.hex verify reset exit'
node tools/motor_diagnostics.mjs --serial 01290141524300143638414B --elf build/frictionless-diag/ROLLERCAN.elf --mode 12 --current-ma 0 --speed-rad-s 12 --pulse-ms 1250 --duration-ms 2400 --out build/frictionless-unlimited/repeat.json
```

只操作 `--serial` 指定的探头。Node.js 脚本需要 PATH 中的 OpenOCD 和 `arm-none-eabi-nm`，不需要 npm 包。

测试通过 SWD 邮箱提交参数，由 ControlTask 在正常 1 kHz 调度中执行。前 350 ms 静置，随后执行限时电流脉冲，或由 `--speed-rad-s` 指定的临时 PI 驱动到共同初始速度，再切换到待测模式。试验最长 30 秒，原始脉冲最大 250 mA，速度 PI 最大 150 mA、目标速度幅度最大 60 rad/s；达到结束条件、故障或 200 rad/s 测试终止条件时关闭输出。200 rad/s 仅用于限时诊断，不是正式无摩擦模式的速度上限。采样缓冲在结束后冻结，因此读取不会干扰所测运动。正常构建没有邮箱和测试驱动代码。

当前诊断邮箱为 ABI v6：头部 68 字节，新增两个 float32 临时参数 `inertia_gain`、`inertia_tau_ms`；两种采样布局共用 6144 字节缓冲。默认 normal 模式最多 128 条记录，每条 48 字节；除瞬时角度、速度、命令电流、Iq 反馈和 Uq 外，还在 1 kHz 控制循环累积窗口均值。12 阶初步识别使用与速度一致的 8 ms 滤波后的命令电流、`sin(12θ)` 和 `cos(12θ)` 均值；稀疏的主机轨迹不能事后重建这些统计量。当前多阶图谱使用 dense 采集单独识别。`measured_ma` 是噪声较大的瞬时 Iq 反馈，平均损耗拟合主要使用稳态命令电流均值。

`--dense 1` 改为采集试验最后 384 ms 的 1 kHz 轨迹，最多 384 条、每条 16 字节，字段为 `ms`、`angle`、`velocity`、`filtered_command_ma`。它与 normal 布局互斥，且要求非零速度 PI 目标与非零脉冲时长。密集窗口可能跨越 PI 与释放阶段，离线识别需根据时间筛选处于 PI 内的样本；不能把 dense 数据直接用于要求 normal 窗口均值的工具。脚本检查 ABI，必须与实际烧录的诊断固件配套。

可选项：

- `--mode coast`：原有零电压 PWM 行为；`--mode torque-zero`：持续跟踪零电流；`--mode off`：关闭桥臂；`--mode 12`：无摩擦补偿。
- `--friction-ma`、`--viscous-ua`：仅本次运行的实验参数，不自动写 Flash。
- `--scale 0..10`：本次试验的补偿倍率；省略时使用编译默认值。`--cogging-scale 0..2`：本次角度补偿倍率，默认为 1；设为 0 可进行关闭角度补偿的 A/B 对照。这些参数不写 Flash。
- `--inertia-gain 0..8`、`--inertia-tau-ms 5..200`：仅本次试验的额外惯量及滤波时间；省略或填 -1 使用编译默认值。`motor_diagnostics.mjs` 和 `optimize_frictionless.mjs` 都支持这两个覆盖参数，优化器将其固定后比较摩擦/黏性候选，不自动写 Flash。
- `--dense 0|1`：默认 0，使用 normal 统计采样；1 使用上述密集采样，供 `identify_frictionless_dense.mjs` 离线分析角度图谱。
- `--save-mode 12`：显式恢复该模式的编译默认参数并通过正常本地 SAVE 事务保存；其他模式的参数保留。这个选项会写 Flash。
- `--save-mode-limits 12`：仅将该模式的电流上限和安全比例恢复为当前固件默认值，再通过正常 SAVE 事务保存。补偿倍率、摩擦、黏性系数和其他模式参数保留。与 `--save-mode` 互斥。
- 每次试验输出 JSON 轨迹和 OpenOCD 日志。测试正常结束后保持输出关闭；重新烧录正式固件或正常启用输出即可体验。

## 自动辨识与释放测试工作流

工作流分别处理平均损耗、角度扰动和释放后的速度漂移。实机采集都通过上述诊断入口串行完成，调用者必须显式指定 24 位 ST-Link 序列号与已烧录的诊断 ELF；不会自动选择电脑上的其他探头。自动工具不会烧录固件或保存参数，只有明确调用 `motor_diagnostics.mjs --save-mode` 或正常 SAVE 才写入 Flash。

1. 用 [`autotune_frictionless.mjs`](../tools/autotune_frictionless.mjs) 测平均损耗。默认正反 3、6、12、20、30 rad/s 各重复两次，每次速度 PI 运行 5000 ms，总采集 5400 ms。对 `3350 ≤ t < 5350 ms` 的均值按实际时间间隔加权，检查平均速度、加速度趋势、速度波动、电流趋势、角度斜率和控制超时，显式排除未稳态点。模型为 `I = sign(v) × Fc + B × v + bias`，报告每点波动、拟合残差、正反差及重复性。
2. 用 [`identify_frictionless_ripple.mjs`](../tools/identify_frictionless_ripple.mjs) 对 normal 采集目录做纯离线识别。工具利用滤波后的转矩平衡模型，同时拟合库仑摩擦、黏性损耗、电流等效惯量和 12 阶正余弦项，分离速度 PI 导致的加减速电流与真正的角度扰动；不能把 PI 的周期性命令电流直接当作齿槽补偿。缺少相应窗口统计的旧版采集会被跳过。报告包含加/不加角度项的残差、正反方向一致性和逐次采集结果；单次拟合残差降低仍需释放测试验证。需要更密集的角度图谱时，另用 `motor_diagnostics.mjs --dense 1` 采集并由 `identify_frictionless_dense.mjs` 离线分析，不与 normal 统计混用。
3. 用 [`optimize_frictionless.mjs`](../tools/optimize_frictionless.mjs) 在相同初始速度下释放，比较各候选平均摩擦和黏性参数的速度漂移、波动及停转情况。默认正反 6、12、20 rad/s，固定总倍率、角度补偿倍率和所选惯量参数，搜索 Fc 与 B；`--evaluate-only` 仅评估给定候选，`--cogging-scale 0` 用于角度补偿关闭的对照，`--inertia-gain 0` 用于虚拟惯量关闭的对照。选择参数后仍应复核慢转、换向和静置无自启动，再通过正常 SAVE 保存最终结果。

以下数值只是搜索初值示例，最终参数应以辨识、释放测试和本机实际手感为准：

```powershell
node tools/autotune_frictionless.mjs --serial 01290141524300143638414B --elf build/frictionless-diag/ROLLERCAN.elf --out-dir build/frictionless-autotune/loss --speeds 3,6,12,20,30 --repeats 2
node tools/identify_frictionless_ripple.mjs build/frictionless-autotune/loss --out build/frictionless-autotune/ripple.json
node tools/optimize_frictionless.mjs --serial 01290141524300143638414B --elf build/frictionless-diag/ROLLERCAN.elf --out-dir build/frictionless-autotune/release --initial-friction-ma 22 --initial-viscous-ua 304 --scale 0.987 --cogging-scale 1 --inertia-gain 8 --inertia-tau-ms 10
```

平均损耗工具生成 `loss-model.json` 和中文 `loss-model.txt`；释放优化工具生成 `summary.json`、`best.json` 及各次原始采集。Fc 和偏置使用 mA；B 输出 µA/(rad/s)，报告也提供 mA/(rad/s)，转换时相差 1000 倍。两个采集工具均可在原命令后加 `--analyze-only` 重分析已有数据，不启动 OpenOCD；角度识别工具始终只做离线分析。数据目录应分轮保留，以免不同固件、温度或角度零位的结果混合。
